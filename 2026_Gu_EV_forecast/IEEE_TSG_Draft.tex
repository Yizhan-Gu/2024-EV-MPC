\begin{abstract}
This paper presents a reproducible forecast-to-control pipeline for campus electric vehicle (EV) charging, where a fixed rolling model predictive control (MPC) core is coupled with multiple forecasting modules. The key design principle is strict modular fairness: only forecasting is changed, while optimization objectives and constraints remain unchanged. Using \num{335035} cleaned charging sessions and a \SI{15}{min} discretization, we evaluate deterministic, probabilistic, and hybrid methods on both EV-level and charger-level scheduling views. The compared methods include Perfect, NoForecast, Persistence, Statistic, GMM, LSTM, TCN, Transformer, iTransformer, iT-CP90, iT-CP95, TFT-Quantile, DeepAR-Gaussian, and ITCN-ChargerAware. 

The study separates timing and energy forecast quality using arrival/departure distribution errors and arrival-energy profile errors, then maps those errors to control cost and peak outcomes. For the \texttt{2023-07-01} benchmark day, non-oracle EV-level best cost is achieved by iTransformer (\$2412.99, \SI{43.20}{\percent} saving vs. V0G), while the charger-level raw best cost among non-oracle methods is iT-CP90 (\$2133.62, \SI{49.78}{\percent} saving). However, charger-level methods exhibit non-negligible under-delivery gaps, highlighting the need for energy-balance sanity checks when interpreting cost-only rankings. 

This draft documents all implementation assumptions, preprocessing filters, model configurations, evaluation metrics, and artifact paths. It is written to be directly transferable to Overleaf and further revised into a journal submission.
\end{abstract}

\section{Introduction}
Smart charging for large EV fleets requires both accurate demand forecasting and operationally feasible control. In practical deployments, forecast and control modules are often entangled, making attribution difficult: improvements in cost may come from controller changes rather than better forecasts. This work adopts a strict modular protocol: forecast module changes only, MPC core fixed.

The repository already contains a working forecasting-and-MPC stack with deterministic baselines and deep sequence models. This paper-level draft extends that stack into a reproducible comparative framework with probabilistic and charger-aware methods, and aligns all outputs into a single artifact tree suitable for peer review.

\subsection{Main Contributions}
The main contributions are:
\begin{enumerate}
    \item A fair forecast-to-MPC comparison protocol where all methods share the same rolling MPC core, tariff model, and feasibility logic.
    \item A unified notation and metric suite that separates timing quality from energy quality, avoiding ambiguous error reporting.
    \item Integration of probabilistic methods (iT-CP90, iT-CP95, TFT-Quantile, DeepAR-Gaussian) and a charger-focused hybrid method (ITCN-ChargerAware).
    \item Publication-ready artifact curation: all comparison figures in one folder and all result tables in one location.
    \item A transparent sanity-check discussion showing when low cost may be driven by energy under-delivery in charger aggregation.
\end{enumerate}

\begin{equation}

\section{Forecasting Methods}

\subsection{Deterministic Methods}
The deterministic bank includes:
\begin{itemize}
    \item Perfect (oracle benchmark)
    \item NoForecast (empty future forecast)
    \item Persistence (historical day reuse)
    \item Statistic (nonparametric sampling)
    \item GMM (multimodal session sampling)
    \item LSTM, TCN, Transformer, iTransformer (day-profile predictors)
\end{itemize}

For deep models, code settings are:
\begin{itemize}
    \item lookback days: 14
    \item epochs: 15
    \item batch size: 16
\end{itemize}

\subsection{Probabilistic and Hybrid Methods}
\textbf{iT-CP90 / iT-CP95}: conformalized intervals built on iTransformer-TCN blended forecasts. Residual quantiles on calibration windows define interval width.

\textbf{TFT-Quantile}: direct quantile prediction ($p10,p50,p90$) using historical observed inputs and known future calendar inputs.

\textbf{DeepAR-Gaussian}: distributional forecasting via $(\mu_t,\sigma_t)$ and scenario sampling.

\textbf{ITCN-ChargerAware}: hybrid method that forecasts profile first, then reassigns charger ids with time-conditioned historical occupancy probabilities.

\section{Rolling MPC Formulation}

\subsection{Objective}
At each rolling step $k$, optimize remaining horizon costs:
\begin{equation}
\min \; C = C_{\mathrm{demand}} + C_{\mathrm{energy}} + C_{\mathrm{other}}.
\end{equation}
Where:
\begin{align}
C_{\mathrm{demand}} &= r_{\mathrm{nc}}\gamma_{\mathrm{nc}} + r_{\mathrm{on}}\gamma_{\mathrm{on}},\\
C_{\mathrm{energy}} &= \sum_{t=k}^{N} r_t L_t\Delta t,\\
C_{\mathrm{other}} &= \beta_1(C_{\mathrm{demand}}+C_{\mathrm{energy}})+\beta_2\sum_{t=k}^{N}L_t\Delta t.
\end{align}

\subsection{EV-Level Constraints}
For active session $i$:
\begin{align}
0 \le p_{i,t} \le P_{\max},\\
\sum_{t=\max(k,\AT_i)}^{\DT_i} p_{i,t}\Delta t = \ED_i^{\mathrm{rem}},\\
L_t = \sum_i p_{i,t}.
\end{align}

\subsection{Charger-Level Constraints}
Sessions are aggregated by charger $c$:
\begin{align}
0 \le p_{c,t} \le P_{\max}\cdot \mathrm{occ}_{c,t},\\
\sum_{t=k}^{N} p_{c,t}\Delta t = E_c^{\mathrm{rem}},\\
L_t = \sum_c p_{c,t}.
\end{align}

\subsection{Solver and Practical Safeguards}
\begin{itemize}
    \item Solver: CBC via PuLP.
    \item Rolling solve time limit per step: 4 s in the reported experiments.
    \item EV-level tractability cap: if work-set sessions exceed 160, keep earliest subset.
    \item If a step is non-optimal, apply fallback dispatch at current interval to maintain continuity.
\end{itemize}

\section{Experimental Protocol}

\subsection{Train/Test Setting}
Configured test dates are 2023-07-01, 2023-07-02, and 2023-07-03. This draft reports detailed quantitative discussion for 2023-07-01, because all updated figures and refined tables are synchronized for that day.

\subsection{Metrics}
\textbf{Timing quality}:
\begin{equation}
\Wone_{\AT}=W_1(\hat{A}_t,A_t),\quad \Wone_{\DT}=W_1(\hat{D}_t,D_t).
\end{equation}

\textbf{Energy quality}:
\begin{align}
\MAE_E &= \frac{1}{96}\sum_t |\hat{E}_t-E_t|,\\
\RMSE_E &= \sqrt{\frac{1}{96}\sum_t(\hat{E}_t-E_t)^2},\\
\mathrm{Err}_{\Sigma E}(\%) &= \frac{|\sum_t\hat{E}_t-\sum_tE_t|}{\sum_tE_t}\times 100.
\end{align}

\textbf{Control metrics}: MPC cost, saving vs. V0G, peak load, delivered energy, and status ratio.

\textbf{Sanity check metric}:
\begin{equation}
\mathrm{gap}_E(\%) = \frac{E_{\mathrm{dispatch}}-E_{\mathrm{required}}}{E_{\mathrm{required}}}\times 100.
\end{equation}

\section{Discussion}

\subsection{Forecast-Controller Interaction}
The results show a nontrivial interaction between forecast quality and control outcomes:
\begin{itemize}
    \item iTransformer and Transformer show strong EV-side cost performance with moderate timing errors.
    \item CP/TFT variants improve some timing metrics but may have high total daily energy mismatch if profile calibration is not constrained.
    \item Charger aggregation can produce attractive raw costs while still under-delivering energy, so energy-gap checks are necessary.
\end{itemize}

\subsection{EV vs Charger Scope Trade-Off}
Average solver optimal-status ratio is approximately 0.946 for both cases. EV-side energy balance is near exact (gap around numerical zero), while charger-side gaps are systematically negative (mean approximately -7.25\%). This highlights the practical value of dual reporting:
\begin{enumerate}
    \item EV case for strict energy fidelity.
    \item Charger case for scalable operational deployment.
\end{enumerate}

\subsection{Interpreting Probabilistic Methods}
CP methods (iT-CP90/iT-CP95) provide high interval coverage (0.938 and 0.969 in PICP@90), but large interval widths and large total daily energy mismatch indicate that uncertainty calibration should be coupled with dispatch-aware constraints to avoid over-conservative or mis-scaled forecasts.

\section{Ablation and Sensitivity Notes}
A solver sensitivity check is provided in \texttt{tables/solver\_sensitivity\_charger\_0701.csv}. In this run configuration, extending per-step time limits did not materially change charger-case outcomes for selected methods, suggesting that formulation/forecast mismatch dominates over raw MILP time budget in those scenarios.

\section{Limitations and Future Work}
\begin{itemize}
    \item Current deep discussion is centered on one day (2023-07-01); broader multi-day statistical tests should be added for final submission.
    \item Charger-level aggregation under-delivery needs explicit service-level constraints or unmet-demand penalties in the objective.
    \item Probabilistic dispatch should integrate risk constraints directly in MPC rather than only post-hoc evaluation.
    \item Site-level feeder and transformer constraints are not yet modeled.
\end{itemize}

\section{Conclusion}
This draft demonstrates a full reproducible workflow from forecasting to MPC for campus EV charging with deterministic, probabilistic, and hybrid methods under a fixed controller. On the benchmark day, iTransformer is the strongest non-oracle EV-level method, while charger-level rankings are sensitive to energy-balance interpretation. The artifact set is publication-ready for further editing, with all figures and tables organized in a single reproducible directory.
